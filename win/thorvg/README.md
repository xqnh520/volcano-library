# 火山.ThorVG 矢量图形模块

火山视窗类库模块, 把 **ThorVG 1.1.0**(矢量图形与动画引擎)封装为原生中文类库。封装的引擎为 CPU 软件光栅后端, 带 SVG / PNG / JPG / WebP / TVG 图片加载、Lottie 动画、TrueType/OpenType 字体排版与 GIF 保存能力。

全部类名、方法名、参数名、注释均为中文。**单层封装**: 每个公开方法自己在 `@` 嵌入行里调用原生 `thorgw_*` 函数, 不再额外套一层只做转发的"桥接类"。

## 把画面显示到窗口(画板)上

ThorVG 渲染的是内存像素, 要显示到火山界面, 最简路径是**导出 32 位 BMP 交给位图对象, 再画到画板**:

```火山代码
方法 贴图到画板
{
    如果 (画布对象.已创建 () == 假)
    {
        返回 ()
    }
    变量 数据 <类型 = 字节集类>
    数据 = 画布对象.取位图数据 ()            // 32 位 BMP, 内存序 BGRA, 自下而上
    如果 (取字节集长度 (数据) <= 0)
    {
        返回 ()
    }
    变量 位图 <类型 = 位图对象类>
    位图 = 位图对象类.载入位图数据 (数据)
    如果 (位图.为空 ())
    {
        返回 ()
    }
    画板1.清除 ()
    画板1.画图片 (位图, 0, 0, 画板1.取用户区宽度 (), 画板1.取用户区高度 ())
}
```

三条实践经验:

1. **渲染时机要看画板尺寸**: `_创建完毕` 时画板可能还没完成布局, 取到的用户区尺寸不可靠。应在 `_首次激活` 里按当时尺寸 `创建画布` 并渲染, 再贴图。
2. **`画板_绘画` 事件在部分框架版本里不会挂接**。不要依赖它做首次绘制; 用 `_首次激活` 主动贴图, 并把 `画板.自动重画 = 真`。
3. **`位图对象类` 是 GDI 资源类**: 用局部变量即可, 作用域结束自动释放, 不必手动删除。

## 四条必须记住的语义

1. **所有权转移**: 绘制对象经 `画布.加入xxx` / `场景.加入xxx` 之后归宿主所有, 宿主销毁时一并销毁。不要再调用对象的 `释放`; `移除xxx` 会**立即销毁**该对象并把火山侧句柄清零。渐变对象在 `应用到填充/应用到描边` 后同理归属形状。
2. **`变换` 会锁定矩阵**: ThorVG 一旦用 `变换` 设定矩阵, 之后的 `平移`/`旋转`/`缩放` 全部失效。复合变换请用 `ThorVG矩阵.组合 (缩放矩阵, 平移矩阵)` 先合成, 再一次性 `变换`。
3. **矩阵是列向量约定**: 平移分量位于 `e13/e23`(下标 2 与 5)。`组合 (甲, 乙)` 表示"先施加甲, 再施加乙"。
4. **从内存加载图片/字体时数据必须被复制**: ThorVG 的 `Picture::load(data, size, mime)` 默认 `copy=false`, 只保存调用方指针并延迟解析; 火山字节集是临时对象, 方法返回后即释放, 会导致图片"加载成功、尺寸正确、但渲染空白"。桥接层已强制 `copy=true`, 使用者无需关心, 但自己直接调原生 API 时必须注意。

## 单层封装规范(本模块的硬性约定)

- 语义类的方法**直接在方法体里嵌入原生调用**, 不建同功能的转发类。
- 只有需要局部变量、分支、字节集缓冲或对象句柄写入时才用普通方法; 普通方法里可以混写 `@` 嵌入行。
- 普通方法的 `@` 行是原样 C++ 语句, **必须自带分号**; `@嵌入式方法` 的 `@` 行由编译器自动补分号, 且必须是单个表达式。
- 普通方法里不能用 `@sn<this>`(仅限嵌入式方法); 先把成员赋给局部变量, 再用 `@<局部变量>` 引用。
- `@` 行引用火山局部变量必须写 `@<变量名>`; 裸中文名不会被翻译成 C++ 标识符。
- 同一个参数在一条嵌入行里最多引用一次; 需要重复时先赋给局部变量。

## ThorVG UI 界面库

在 ThorVG 画布之上的一整套自绘界面: 控件树、布局引擎、命中测试、状态样式、弹出层与事件分发。
界面完全由矢量路径绘制, 不依赖任何 MFC 控件, 因此悬停/按下/焦点/选中/禁用等状态都能自由定制。

### 架构

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 原生核心 | `native/ui_bridge.cpp` (3269 行, 107 个 C 接口) | 控件树、布局算法、最内层命中测试、状态机、绘制、事件队列、弹出层 |
| 火山封装 | `ThorVG界面.wsv` (5 类 139 方法) | 薄封装 + 可覆盖的虚拟方法钩子 |

原生层绘制统一走 `thorgw_*` C 接口, 不直接使用 `tvg::` C++ API(静态库由另一工具集构建, 跨编译单元传 C++ 对象不安全)。

### 23 种控件

面板、卡片、分组框、标签、按钮、复选框、单选框、开关、滑块、进度条、输入框、多行文本、
下拉框、列表、表格、标签页、数值框、分隔线、滚动条、图片、链接、徽标、菜单。

### 5 种布局

绝对定位(`UIL_ABSOLUTE`)、水平流水(`UIL_HORIZONTAL`)、垂直流水(`UIL_VERTICAL`)、
网格(`UIL_GRID`, 按列数自动换行)、叠层(`UIL_STACK`, 子控件填满父容器, 用于标签页内容)。

支持: 权重伸展(`设置权重`)、内边距、外边距、内容自适应尺寸(宽高传 0 时按文字/内容计算)、
容器滚动(内容超出时自动绘制滚动条)。

### 14 种事件

单击、值改变、文本改变、鼠标进入、鼠标离开、获得焦点、失去焦点、勾选改变、滚动、
选中项改变、项被单击、项被双击、标签页切换、弹出层关闭。

事件先进入队列, 由 `处理事件 ()` 逐条分派到可覆盖的钩子:
`控件被单击` / `控件值改变` / `文本被修改` / `控件勾选改变` / `控件鼠标进入` / `控件鼠标离开` /
`控件获得焦点` / `控件失去焦点` / `容器被滚动` / `控件选中改变` / `控件项被单击` /
`控件项被双击` / `标签页被切换` / `弹出层被关闭`。
也可以改用 `取事件 ()` 手动轮询。

### 性能与避免闪烁

鼠标划过时不应每帧全量重绘。标准做法是「脏标记 + 一次性覆盖贴图 + 整窗双缓冲」:

```火山代码
// 1. 窗口创建时开启整窗双缓冲(WS_EX_COMPOSITED), 子控件重绘不再闪
变量 窗口句柄 <类型 = 变整数>
窗口句柄 = 取窗口句柄 ()
@ ::SetWindowLongPtrW((HWND)@<窗口句柄>, -20, ::GetWindowLongPtrW((HWND)@<窗口句柄>, -20) | 0x02000000L);
画板1.自动重画 = 真

// 2. 鼠标事件后只在状态真的变了才重绘
界面.鼠标移动 (x, y)
界面.处理事件 ()
如果 (界面.取脏标记 ())
{
    刷新界面 ()
}

// 3. 贴图时不要先 画板.清除 (), 直接整幅覆盖(一步完成, 没有"先白后画")
画板1.画图片 (缓存位图, 0, 0, 画板1.取用户区宽度 (), 画板1.取用户区高度 ())
```

`取脏标记 ()` 是消费型的: 悬停控件切换、按下/抬起、取值/勾选/选中/展开/滚动/焦点变化、
以及任何 `设置xxx` 调用都会置位, 读取一次后清除。所以在同一个控件内部移动鼠标**完全不重绘**,
只有跨过控件边界时才会重绘一帧。

实测(原生探针): 在按钮内连续移动 10 次, 脏标记始终为 0; 移到别的控件时为 1。

如果要进一步降频(例如渲染很重的界面), 可以在 `取脏标记` 为真时再叠加时间节流
(距上次重绘小于 16 ms 就跳过, 标记不清除, 下一帧继续尝试)。

### 已知限制

- 输入框只支持追加/退格/方向/Home/End, 没有选区、复制粘贴与输入法(IME)支持。
- 事件需在鼠标/键盘事件后主动调用 `处理事件 ()` 并重绘, 没有内部定时器。
- 图片控件每帧重建图片对象(加入画布的对象归画布所有), 大图有额外开销。
- 绘制全量重建, 控件数百以上建议自行分帧。

## 依赖说明 / 静态库的两个关键构建约束

ThorVG 由源码以 Meson + MSVC 自建, x64, `engines=cpu`、`loaders=all`、`savers=all`、`simd=true`、`threads=true`。

**约束 1: 用最旧的 MSVC 工具集构建(本机 14.29.30133), 不要用最新的。**
火山调试版链接的是 MFC 静态调试库 `uafxcwd.lib`, 它内嵌的 CRT 比较旧, 不提供
MSVC 14.4x 新版 STL 的内部符号(如 `__std_find_last_of_trivial_pos_1`、
`__std_min_element_f`)。用 14.4x 构建的库会引用这些符号, 在 IDE 里链接时报
`LNK2019 无法解析的外部符号`。
兼容性规则: **旧 STL 编译的对象可以被新工具集链接, 反之不行** —— 所以统一用最旧工具集构建,
库就能被任何宿主配置链接。

**约束 2: 必须关闭 ThorVG 的全局 `operator new` 重载。**
ThorVG 在 `src/renderer/tvgInitializer.cpp` 里无条件重载了全局 `operator new/delete`
(走它自己的内存池), 而 `uafxcwd.lib(afxmem.obj)` 也定义了这四个符号, 链接时报
`LNK2005 operator new 已经在 ... 中定义`。
本模块已在 `tvgCommon.h` / `tvgInitializer.cpp` 给这些重载加了 `THORVG_NO_GLOBAL_NEW`
开关, 构建时通过 `-Dcpp_args=-DTHORVG_NO_GLOBAL_NEW` 定义宏即可关闭。

重建命令(在 `deps/thorvg-1.1.0` 下, 先 source `E://AI开发//ThorVG//build_env_1429.sh`):

```
:: 发布版 /MT
meson setup build-r -Dbuildtype=release -Db_vscrt=mt -Db_ndebug=false \
      -Ddefault_library=static -Dengines=cpu -Dloaders=all -Dsavers=all \
      -Dsimd=true -Dthreads=true -Dlog=false -Dtests=false -Dbindings= \
      -Dcpp_args=-DTHORVG_NO_GLOBAL_NEW
meson compile -C build-r

:: 调试版 /MTd (参数同上, 改 buildtype=debug、b_vscrt=mtd)
```

产物 `build-r/src/libthorvg-1.a` / `build-d/src/libthorvg-1.a` 分别重命名为
`thorvg-1release.lib` / `thorvg-1debug.lib` 放入 `deps\thorvg\lib\`。

自检(必须两项都为空/0):

```
dumpbin /symbols thorvg-1release.lib | findstr "SECT.*??2@YAPEAX_K@Z"     :: 应无输出
dumpbin /symbols thorvg-1release.lib | findstr "__std_find_last_of"      :: 应无输出
```
