# Skia 全量封装 · 系统架构设计

> 目标：把 `deps\skia\bin\x64\libSkiaSharp.dll`（x64，856 导出）的 C API 全量封装成火山视窗类库。
> 数据基线来自 `native\skia_api.json`（用 python 核对）：**funcs 850 / exported 850 / 未导出 0（2026-10-30 复核修正）/ enums 63 / structs 51 / 头文件 43（38 个含函数）**。
> 关联文档：`命名映射-批次1.md`（命名权威）、`值类清单.md`（结构体字节与偏移权威）。

> ## ⚠ 实测修订（优先级高于本文件正文）
>
> 以下四条在本文件写作时未经验证，落地后已被实测推翻，**以本节为准**：
>
> 1. **所有权：`类_清理` 一律空实现，句柄必须由调用方显式 `释放 ()`。**
>    正文里“`类_清理` → 内部调用 `释放()`，忘记释放也不会泄漏”的设计**作废**。
>    原因：火山类值语义（赋值/传参/返回均复制），多个火山对象共享同一原生指针，`类_清理` 里 delete 会重复释放；实测首次 `画笔 = Skia画笔.新建 ()` 即崩 `0xC0000374 STATUS_HEAP_CORRUPTION`。ThorVG / OCCT 官方模块同为显式释放约定。
> 2. **`@视窗.预定义宏` 不带 `NOMINMAX`。** 该属性是项目级，会让消费方 MFC 工程的 `GdiplusTypes.h` 报 `C3861 min/max 未定义`。只保留 `_CRT_SECURE_NO_WARNINGS`。
> 3. **`@视窗.外部库.x64` 写死 `libSkiaSharp.lib`，不用 `$(d)`**（`$(d)` 会展开成 `libSkiaSharprelease.lib` → `LNK1181`）。
> 4. **`skia.vgrp` 只收录类库文件**；`Skia冒烟.wsv` 是测试桩，由测试工程单独引用，不得进模块。
>
> 另：值类 setter 的形参不得与同类方法名重名（`参数 上` 与 `方法 上` 并存时 `@<上>` 会解析成方法，静默读回错值），已统一改为 `左边/上边/右边/下边`、`横值/纵值`、`宽值/高值`、`红值/绿值/蓝值/透明度值`。

### 2.1 句柄类的 创建/释放/类_清理 取向（与 ThorVG 对齐）
- 统一两个成员：`变量 对象指针 <公开 类型 = 变整数>`、`变量 是否拥有句柄 <公开 类型 = 逻辑型 值 = 真>`。
- `方法 类_清理` → 内部调用 `释放()`，实现"忘记释放也不会泄漏"；`释放()` **公开且可重复调用**（`对象指针 == 0` 直接返回真；释放后把 `对象指针` 与 `是否拥有句柄` 复位）。
- **借用句柄必须 `是否拥有句柄 = 假`**：所有 `get_xxx`（`sk_paint_get_shader`、`sk_image_get_colorspace`、`sk_surface_get_canvas`、`sk_canvas_get_surface` 等）返回的包装对象都不释放，`类_清理` 只清零。唯一例外是 `sk_pathbuilder_detach_path` —— 它是**转移所有权**。
- 只有 `unref` 的类型（image/shader/3 类 filter/typeface/textblob/colorspace/data/surface/vertices/blender/picture/path_effect）→ `释放()` 只调对应 unref，**不自己再减引用**。
- 只有 `new/delete` 的类型（canvas/paint/path/pathbuilder/rrect/region/pathmeasure/opbuilder/bitmap/pixmap/string/font/fontmgr/fontstyle/document/游标）→ `释放()` 调 `_delete/_destroy`。
- **强制约定**：`Skia表面.取画布` 得到的 `Skia画布` 绝不能释放（`sk_canvas_destroy` 是 `delete`，会删掉 surface 内部 canvas → 立即崩溃/双重释放）。这是 `是否拥有句柄` 存在的首要理由。

## 三、值类型（51 个结构体）策略

### 结论：**不用 `@视窗.结构类`，改用"值类 = 普通类 + 私有 `数据:字节集类` 缓冲 + 属性读/置XXX + 嵌入行取址"**

理由（4 条，按重要度）：
1. **火山类的成员不是连续 C 结构**：普通类的 `小数` 成员是分散的 C++ 成员，`&对象` 得到的不是 `sk_rect_t`。`@视窗.结构类` 虽会生成 `类名::S` 与 `S* GetStruct(S*)/void SetStruct(const S*)`，但这两个是**普通方法**，在 `@嵌入式方法` 的单表达式里无法调用（嵌入行只能写裸 C++ 表达式）。会退化成"普通方法 + 局部变量 + 一次 native 调用"，canvas 30+ 个绘制 API 每个多 3~4 行，代码量翻倍。
2. **`@视窗.结构类` 要求所有成员都是基本数据类型/结构类/其数组**。但 `sk_imageinfo_t` 有 `sk_colorspace_t* colorspace`、`sk_lattice_t` 有 4 个数组指针、`sk_document_pdf_metadata_t` 有 8 个指针 —— 只能用 `变整数` 硬塞，可读性与安全性都差；字节集类缓冲法里 `((sk_imageinfo_t*)p)->colorspace = nullptr;` 是类型安全的。
3. **ThorVG 已实测通过同一手法**（`ThorVG矩阵` 用 36 字节 `字节集类` + `@<数据>.GetPtr()` 强转）。复制成熟范式比开辟新路便宜。
4. 全部结构体尺寸是 4/8 的整数倍，字节集类堆内存天然 8 字节对齐，无需对齐参数。精确尺寸与字段偏移见 `值类清单.md`。

### 值类形状（工程师照抄）

```
    }

    方法 置左 <公开 类型 = 逻辑型 折叠 @嵌入式方法 = "">

}
```
> `置左` 用逗号表达式把赋值包成单一表达式并返回 `真`。四边同置另给 `方法 置边界(左/上/右/下)`（避免一个参数在一行内多次引用）。

### 在其它类的嵌入行里取址（两种写法，首选 A）
- **A（首选，单表达式零开销）**：`(const sk_rect_t*)@<矩形>.@n<Skia矩形.数据>.GetPtr()`
  依据：pitfalls 1193 行"读取参数成员合法" + `vol_win_full.md` 1356/1374 行 `@sn<this>.data().GetMem()` 的链式写法。
- **B（兜底）**：值类加 `方法 取地址 <公开 类型 = 变整数>`（普通方法，返回 `.GetPtr()` 的 `intptr_t`）；调用方先 `变量 矩形地址 <类型 = 变整数>` / `矩形地址 = 矩形.取地址 ()`，再 `@ ... (const sk_rect_t*)@<矩形地址> ...`。仍然只有一次 native 调用，不违反单层嵌入。
- **T01 第一件事：写 3 行探针（画矩形 + 取边界）确认 A 能编译**；A 不通就全库统一切 B（取地址方法统一命名 `取地址`，便于一次性替换）。

### 51 个结构体归类
- **纯数值值类（可用缓冲法，31 个）**：几何（点/点3/尺寸/整数尺寸/点整数/矩形/整数矩形/旋转缩放/矩阵/矩阵44）、颜色（浮点颜色）、选项（采样选项/三阶采样/图像信息/图层记录/PNG·JPEG·WebP 编码选项/WebP 帧/解码选项/帧信息/高对比度配置/XPS 选项）、字体（字体度量/调色板覆盖/变量轴/变量轴坐标）、运行时效果（变量/子项）、文字块缓冲、PDF 时间/元数据。

## 四、关键设计决策

1. **单层嵌入、无桥接类**：`Skia画布.绘制矩形` 的方法体直接 `@ sk_canvas_draw_rect(...)`。**不建 `Skia原生` 转发类**（pitfalls 1129 行明令）。整个模块不需要任何 `.cpp`；只用一个 `native\skia_include.h` 伞头（`#include` 43 个头 + `<cstdint>`），通过 `"@视窗.外部头文件.全局-100" = "skia_include.h"` 引入 —— 纯 include，不含转发函数，不违反铁律。**不需要 `@视窗.外部源文件`**。
2. **句柄一律 `变整数`**（`intptr_t`），不定义自定义指针类型；`0` = 无效句柄。所有方法在句柄为 0 时**先返回失败/默认值，绝不下传**（Skia C API 对 null 句柄普遍直接崩）。
3. **空句柄契约**：`Skia画笔.置着色器/置遮罩滤镜/置颜色滤镜/置图像滤镜/置混合器/置路径效果` 允许传句柄 0 的对象 = **清除该特效**（合法用法，嵌入行传 `nullptr`）；`Skia画布.保存图层` 的边界/画笔可空；`Skia画布.绘制图片` 的矩阵/画笔可空；`Skia区域.置路径` 的裁剪区域可空。其余参数**不接受空对象**。
4. **像素格式约定**：默认 **`BGRA_8888` + `PREMUL_SK_ALPHATYPE`**（Skia 光栅默认，也是 Windows DIB 能直接吃下的顺序；`sk_colortype_get_default_8888()` 实测 = 6 = BGRA_8888）。`Skia图像信息` 提供 `新建(宽,高)` 与 `新建_完整(宽,高,颜色类型,透明度类型,颜色空间)`。涉及红蓝差异处提供 `Skia颜色.交换红蓝通道` 兜底。
5. **`size_t` 一律 `变整数`**（x64 是 64 位，用 `整数` 会截断）。涉及：`sk_data_get_size`、`sk_string_get_size`、`sk_pixmap_get_row_bytes`、全部 `sk_graphics_get_*`、`sk_codec_*`、`sk_wstream_get_size`。
6. **字节集类交互**：
   - 建 `sk_data`：`@ sk_data_new_with_copy((const void*)@<数据>.GetPtr(), (size_t)@<数据长度>)`
   - 取 `sk_data`：普通方法，`@ @<长度> = (intptr_t)sk_data_get_size(...);` → `数据 = 取空白字节集类 (长度)` → `@ memcpy(@<数据>.GetPtr(), sk_data_get_data(...), (size_t)@<长度>);`（普通方法内的 `@` 行是裸 C++，**必须自带分号**）
7. **文本参数/返回**：`const char*` 入参用 `(const char*)GetMbsText(@<文字>.GetText(), CVolMem(), NULL)`（已实测，见 `vol_win_full.md` 1356 行）在单条表达式内完成 UTF-16→UTF-8；返回 `const char*` 用 `@ @an<CVolString>((const char*)...)`。需"文本 + 字节数"两参数的（`sk_canvas_draw_simple_text`）走普通方法：先 `变量 缓冲 <类型 = 字节集类>` / `@ @<缓冲> = GetMbsText(...);`，再取 `.GetPtr()` / `.GetSize()`。
8. **逻辑型/整数边界**：native `bool` → `@ (sk_xxx(...) != 0)`；native `int` 保持 `整数`，语义层再判断。⚠ `sk_canvas_save/save_layer` 返回的是**保存层数**（≥1），不是布尔，不能用 `== 1` 判成功。
9. **枚举一律用 `整数` + 注释列值**，不建 63 个常量类（值全部从 0 顺序递增，已核对头文件）。必记：`sk_paint_style_t` FILL=0/STROKE=1/STROKE_AND_FILL=2；**`sk_clipop_t` DIFFERENCE=0 / INTERSECT=1（常规裁剪必须显式传 1，传 0 会变成挖洞）**；`sk_pathop_t` DIFF=0/INTERSECT=1/UNION=2/XOR=3/REVERSE_DIFF=4；`sk_region_op_t` 同上 + REPLACE=5；`sk_path_verb_t` MOVE=0/LINE=1/QUAD=2/CONIC=3/CUBIC=4/CLOSE=5/DONE=6；`sk_path_filltype_t` WINDING=0/EVENODD=1/INVERSE_WINDING=2/INVERSE_EVENODD=3；`sk_pathmeasure_matrixflags_t` POS=1/TAN=2/BOTH=3；`sk_stroke_cap_t` BUTT/ROUND/SQUARE=0/1/2；`sk_stroke_join_t` MITER/ROUND/BEVEL=0/1/2；`sk_path_direction_t` CW=0/CCW=1；`sk_path_arc_size_t` SMALL=0/LARGE=1；`sk_filter_mode_t` NEAREST=0/LINEAR=1；`sk_point_mode_t` POINTS/LINES/POLYGON=0/1/2；`sk_alphatype_t` UNKNOWN/OPAQUE/PREMUL/UNPREMUL=0/1/2/3。
10. **包/文件划分**（一个 vgrp、8 个 wsv）：
    `Skia核心.wsv`（包属性 + 全局 + 颜色 + 矩阵 + 数据 + 字符串）、`Skia绘制.wsv`（画布族 + 画笔）、`Skia几何.wsv`（路径族 + 圆角矩形 + 区域）、`Skia图像.wsv`（图像/位图/像素图/表面/编解码/流/图片）、`Skia文字.wsv`（字体/字形/文字块/文字工具）、`Skia效果.wsv`（着色器/三类滤镜/混合器/运行时效果/顶点/颜色空间）、`Skia文档.wsv`（PDF/XPS）。
    包属性：`@视窗.头文件搜寻目录 = "deps\\skia\\include\\c"` + `"native"`、`"@视窗.外部头文件.全局-100" = "skia_include.h"`、`@视窗.库文件搜寻目录.x64 = "deps\\skia\\lib\\x64"`、`@视窗.外部库.x64 = "libSkiaSharp$(d).lib"`、`@视窗.预定义宏 = "NOMINMAX,_CRT_SECURE_NO_WARNINGS"`、`@视窗.附加编译参数 = "cpp: /std:c++17 /bigobj"`。

## 五、待明确事项

1. **`@<参数>.@n<值类.数据>.GetPtr()` 链式取址是否合法** —— 决定全库值类写法 A/B。T01 必须先跑 3 行探针。
2. **`sk_canvas_destroy(surface 的 canvas)` 是否真会 `delete`**：头文件未写所有权。设计按"绝不释放"处理（`是否拥有句柄 = 假`）。同理 `sk_get_surface(canvas)` 返回新引用还是借用引用未定 → 一律按借用处理。
3. **`sk_paint_set_shader/set_maskfilter/set_colorfilter/set_imagefilter/set_blender/set_path_effect` 的所有权**：是否 `ref()` 未知。保守策略：**置入后把火山侧句柄清零（视为移交所有权）+ 注释说明不可复用**；若实测是 ref 语义，改为保留句柄（更友好）。影响 8 个方法，需一次实测。
4. **对象只能一次性使用**（**2026-10-30 已推翻**：`sk_shader_ref`/`sk_maskfilter_ref`/`sk_data_ref`/`sk_textblob_ref`/`sk_picture_ref`/`sk_vertices_ref` **全部已导出**，可加引用后复用；原判断是清单漏抓所致），说明这些对象在本 DLL 里无法加引用。必须强化"借用 = 不释放"与"一个对象只置入一次"的契约，否则 refcount 提前归零。**建议对着色器/图像滤镜再跑一次 refcount 探针。**
5. **`sk_fontstyleset_unref` 已导出**（2026-10-30 复核）：`Skia字体样式集` 释放路径不完整，可能只能"从不释放"。
6. **`sk_image_make_shader` 返回的 shader 是否 ref 了 image**：若是，`Skia图像` 不能先释放（用户极易踩）。
7. **`sk_surfaceprops_*`**：`NONE=0 / USE_DEVICE_INDEPENDENT_FONTS=1`；需确认 `sk_surface_new_raster` 是否接受 `nullptr` props —— 若接受则"属性参数可为空对象"。
8. **`sk_canvas_draw_simple_text` 的 `byte_length` 必须是 UTF-8 字节数**（中文每字 3 字节），注释写死，并提供 `Skia画布.绘制文字(文字:文本型,…)` 自动量长度的便利方法。
9. **`const` 不一致**：`sk_pixmap_get_writable_addr(const sk_pixmap_t*)` 返回 `void*`。需逐函数核对 const，避免嵌入行传错导致 C2440。
10. **字体/文字域（批次 3）风险最高**：`sk_typeface` 46 个函数含 `sk_typeface_unichars_to_glyphs`、`sk_font_get_paths` 等指针数组接口，需单独一轮设计。批次顺序建议：批次1 几何/绘制 → 批次2 图像/编解码/流/表面 → 批次3 文字/字体 → 批次4 效果/滤镜/着色器/颜色空间/文档。
11. **`sk_colorspace_*` 的不透明类型缺签名**：`sk_colorspace_icc_profile_t*`、`sk_colorspace_xyz_t*`、`sk_colorspace_transfer_fn_t*` 不在 51 个 structs 内（是 `sk_types.h` 里的不透明 struct 或 inline struct），批次 4 前需补一轮头文件解析。
12. **`sk_runtimeeffect_uniform_t` 的字段名 `min`/`def`/`max`**（`sk_fontarguments_variation_axis_t` 同名）：已通过 `NOMINMAX` 规避 `min/max` 宏，但工程内不得再 `#define min/max`。
