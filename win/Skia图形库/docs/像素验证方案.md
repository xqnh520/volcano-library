# Skia 封装 · 像素级功能验证方案

> **状态：设计完成，待执行。** 本方案需要批次2（`Skia图像信息` 值类 / `Skia表面` / `Skia位图`）落地后才能跑。
> 关联：`docs/封装流程.md`（守门流程）、`docs/命名映射-批次1.md`（方法名权威）、`docs/值类清单.md`（结构体布局）。
>
> 冒烟闸门（`tools/smoke.py`）只证明「能编译」。**本文件解决「画出来的像素对不对」。**
> 原则：**每一条断言都必须是精确 ARGB 值或精确像素计数，不允许"看起来对"。**

---

## 一、统一前提（所有用例共用）

| 项 | 取值 | 依据 |
|---|---|---|
| `colorType` | `6` = `BGRA_8888_SK_COLORTYPE` | `deps/skia/include/c/sk_types.h` 枚举顺序（UNKNOWN=0, ALPHA_8=1, RGB_565=2, ARGB_4444=3, RGBA_8888=4, RGB_888X=5, **BGRA_8888=6**） |
| `alphaType` | `2` = `PREMUL_SK_ALPHATYPE` | `sk_types.h`：UNKNOWN=0, OPAQUE=1, **PREMUL=2**, UNPREMUL=3 |
| 像素内存布局 | 每像素 4 字节，顺序 **B,G,R,A** | BGRA_8888 字面定义 |
| 读成 uint32（小端） | `A<<24 \| R<<16 \| G<<8 \| B` = **0xAARRGGBB** | 小端机器上 B,G,R,A 四字节按低→高地址正好拼成 0xAARRGGBB |
| `rowBytes` | `宽 × 4`（不 padding） | 简化断言；实际封装若要 padding 必须在本文件更新 |
| 画布尺寸 | 默认 **200×200**（用例4/5 用 800×600） | 够用且快 |

> **选择 `alphaType = 2(PREMUL)` 的理由**：Skia 内部与所有绘制路径都按预乘处理，读回的是预乘值。
> 若选 `OPAQUE(1)`，带 alpha 的叠加结果与「非预乘直觉」不一致，容易把正确结果判成失败。
> **每个用例都必须写明用了哪个 alphaType —— 换 alphaType 等于换了一套期望值。**

### 像素读取方式（三条，推荐第 1 条）

| 编号 | 方式 | 需要的封装 | 说明 |
|---|---|---|---|
| **R1（推荐）** | 画布直接画进**自己持有的 `字节集类` 缓冲**，然后读内存 | 只需 `Skia画布.新建_按像素`（**批次1 已有**）+ `Skia图像信息` | 零额外 API，最可控，失败能立刻 dump 整块缓冲 |
| R2 | `sk_surface_peek_pixels` + `sk_pixmap_get_pixel_color` | `Skia表面`、`Skia像素图` | 语义最正规，但要两个新句柄类 |
| R3 | `sk_surface_read_pixels(surface, dstInfo, dstPixels, dstRowBytes, srcX, srcY)` | `Skia表面` + 还要再造一个 `Skia图像信息` 作 dstInfo | 最啰嗦 |
| R4 | `sk_bitmap_get_pixel_colors(bitmap, colors)` | `Skia位图` | 一次拷出全部像素，适合整块比对 |

**本方案按 R1 设计**，并给出 R2/R4 的等价读法（执行时二选一，结果必须一致）。

### R1 的调用序列（骨架）

```
变量 宽 <类型 = 整数>        ： 200
变量 高 <类型 = 整数>        ： 200
变量 行字节 <类型 = 整数>     ： 800            // 宽 × 4
变量 缓冲 <类型 = 字节集类>   ： 取空白字节集类 (200 * 200 * 4)
变量 信息 <类型 = Skia图像信息>
变量 画布 <类型 = Skia画布>

信息.置尺寸 (200, 200)            // width / height
信息.置色彩类型 (6)               // BGRA_8888
信息.置透明度类型 (2)             // PREMUL
信息.置颜色空间 (0)               // nullptr = sRGB
画布 = Skia画布.新建_按像素 (信息, 缓冲.取字节集类指针 (), 行字节, 空对象)
画笔.置抗锯齿 (假)                // ★ 无 AA 是精确断言的前提
... 绘制 ...
// 读像素：(x, y) 的 uint32
值 = 取字节集类数据 (缓冲, y * 行字节 + x * 4, 整数)
画布.释放 ()
```

两个**必须验证的前置事实**（用例 0 就是验这个）：

1. `新建_按像素` 是「接管外部内存不拷贝」，所以 `画布.释放 ()` **不能**把我们自己的 `缓冲` 释放掉。
2. `缓冲.取字节集类指针 ()` 拿到的地址在画布存活期内稳定（`字节集类` 没有扩容重分配）。

> 如果 `Skia图像信息` 的置值方法名与上面不同，以模块内（`Skia核心.wsv` / `Skia几何.wsv`）实际声明为准；本方案只依赖「能设 width/height/colorType/alphaType 四个字段」这一能力。

## 二、用例

每条都写：**目的 / 序列 / 读取 / 期望 / 容差 / 失败定位**。

### 用例 0：环境自检（先跑，不通过则后面全部无意义）

- **目的**：证明像素目标能建、能清、能读回、释放不崩。
- **序列**：建 200×200 画布 → `清空 (0xFFFFFFFF)` → 读 5 个点 → `画布.释放 ()` → 再 `画布.释放 ()` 一次（验证可重复调用）。
- **期望**：5 个点全部 `0xFFFFFFFF`；两次 `释放 ()` 都返回真且进程不崩。
- **容差**：0。
- **失败定位**：
  - 全不是 `0xFFFFFFFF`（比如全 0）→ 像素地址没接上，或 `行字节数` 传错（传成 200 而不是 800）。
  - 是 `0x00FFFFFF` → `alphaType` 设成 `UNPREMUL(3)` 了。
  - 第二次 `释放` 崩 → 句柄没有清零，重复 `sk_canvas_destroy`。

### 用例 1：填满纯红

- **目的**：验证「全画幅单色填充」的通道顺序与 alpha。
- **序列**：用例 0 的画布 → `清空 (0xFFFF0000)`（ARGB 32 位，`sk_canvas_clear` 不做混合）。
- **读取**：`(0,0)`、`(199,0)`、`(0,199)`、`(199,199)`、`(100,100)` 五个点。
- **期望**：五点全部 **`0xFFFF0000`**。
- **容差**：**0（精确相等）**。纯 `clear` 不涉及光栅化，任何偏差都是封装 bug。
- **失败定位**：
  - 读成 `0xFF0000FF` → BGRA/RGBA 搞反了（`colorType` 用了 4 而不是 6，或字节偏移写成了 `R,G,B,A`）。
  - 读成 `0x00FF0000` → alpha 通道没写进去（`清空` 的参数被当成了 RGB 而不是 ARGB）。
  - 只有部分点对 → `行字节数` 与实际 stride 不一致，越往后越偏。

### 用例 2：抗锯齿关闭的 100×100 矩形

- **目的**：验证几何边界落在**精确像素**上（左闭右开）。
- **序列**：`清空 (0xFFFFFFFF)` → 画笔 `置抗锯齿 (假)`、`置样式 (0)`（填充）、`置颜色 (0xFF00FF00)` → `绘制矩形 (矩形(10,10,110,110), 画笔)`。
- **读取**：
  - 内部三点：`(10,10)`、`(109,109)`、`(60,60)`
  - 紧邻外侧四点：`(9,10)`、`(110,10)`、`(10,9)`、`(10,110)`
- **期望**：
  - 内部三点 **全部 `0xFF00FF00`**
  - 外侧四点 **全部 `0xFFFFFFFF`**
- **容差**：**0（精确相等）**。AA 已关 + 整数坐标 ⇒ Skia 覆盖区间是 `[left, right) × [top, bottom)`，边界像素属于哪一侧是确定的。
- **失败定位**：
  - 外侧点变成绿色 → 边界取成了闭区间（`<=`），或矩形坐标多算了 1。
  - 内部点不是纯绿而是花点 → **抗锯齿没关掉**（`置抗锯齿 (假)` 没生效，或被后面的 `重置 ()` 清掉了）。
  - 只有左边/上边对 → `right/bottom` 传参顺序错（`sk_rect_t` 是 left,top,right,bottom）。

### 用例 3：描边线宽 4 的竖线

- **目的**：验证描边的**中心对齐**与像素覆盖宽度。
- **序列**：`清空 (0xFFFFFFFF)` → 画笔 `置抗锯齿 (假)`、`置样式 (1)`（描边）、`置线宽 (4.0)`、`置颜色 (0xFF000000)` → `绘制直线 ((50,0), (50,99), 画笔)`。
- **读取**：扫描 `y = 50` 这一整行（x = 0..199），统计「颜色 ≠ `0xFFFFFFFF`」的像素个数与它们的 x 坐标。
- **期望**：
  - 覆盖像素数 **= 4**
  - 覆盖的 x 坐标 **= {48, 49, 50, 51}**
  - `x = 47` 与 `x = 52` 均为 `0xFFFFFFFF`
- **容差**：覆盖数 **3 ~ 5**（验收门槛按区间），但**必须同时记录精确值**：精确值应为 4，若落成 3 或 5 要单独标为「取整可疑」并让工程师确认。
  理由：描边以路径为中线，线宽 4 ⇒ 覆盖 `[50-2, 50+2) = [48,52)`；若封装做了像素中心 0.5 偏移，会变成 `{47,48,49,50}` 或 `{49,50,51,52}` —— 这是**可接受的实现差异，但必须记录实际值**，不能默默放过。
- **失败定位**：
  - 覆盖数 = 1 → `置线宽` 没生效（默认细线 1px）。
  - 覆盖数 = 8 → 线宽被当成半径用了。
  - 像素是灰色的 → AA 没关（AA 会让边缘变成半透黑，颜色不等于 `0xFF000000`）。
  - 整行全黑/全白 → `置样式` 传错（0 填充 vs 1 描边），填充模式下画线几乎不可见。

### 用例 4：裁剪矩形后绘制

- **目的**：验证 `裁剪方式` 语义（**0 挖去 / 1 取交**，传 0 会变成挖洞 —— 这是最容易踩的坑）。
- **序列**：800×600 画布 → `清空 (0xFFFFFFFF)` → `裁剪矩形 (矩形(0,0,100,100), 1, 假)` → `绘制颜色 (0xFF0000FF, 1)`。
- **读取**：`(50,50)`、`(99,99)`、`(100,100)`、`(400,300)`、`(0,0)`
- **期望**：
  - 裁剪内：`(50,50)`、`(99,99)`、`(0,0)` = **`0xFF0000FF`**
  - 裁剪外：`(100,100)`、`(400,300)` = **`0xFFFFFFFF`**（保持背景）
- **容差**：**0（精确相等）**（AA 参数传 `假`）。
- **失败定位**：
  - 反过来了（内部白、外部蓝）→ `裁剪方式` 传成了 0（挖去），必须传 1（取交）。
  - 全画幅都变蓝 → 裁剪没生效（画布没进 `保存状态`/`恢复到保存层数` 也应当生交，但若封装把 clip 调用丢了就会这样）。
  - 边界 `(99,99)` / `(100,100)` 都对但 `(0,0)` 不对 → 裁剪矩形坐标传参顺序错。

### 用例 5：半透明红叠加白底（容差用例）

- **目的**：验证预乘 alpha 的 SrcOver 混合算术。
- **序列**：800×600 画布（`alphaType = 2 / PREMUL`）→ `清空 (0xFFFFFFFF)`（不透明白）→ `绘制颜色 (0x80FF0000, 3)`（alpha=0x80=128，混合方式 3 = SrcOver）。
- **手工推导**（这是期望值的来源，不是猜的）：
  - src 预乘：`R = 255×128/255 = 128`，`G = B = 0`，`A = 128`
  - dst 预乘：`R = G = B = 255`，`A = 255`
  - SrcOver 系数 `k = (255-128)/255 = 127/255`
  - 结果：`R = 128 + 255×127/255 = 128 + 127 = 255`；`G = 0 + 127 = 127`；`B = 127`；`A = 128 + 127 = 255`
- **期望**：**`0xFFFF7F7F`**（R=255，G=B=127）
- **容差**：
  - 每通道 **±1**（Skia 有 `(a+1)` 形式的舍入，`127` 可能出 `126`/`128`）
  - 推荐断言写法：`R ∈ [254,255]`、`G ∈ [126,128]`、`B ∈ [126,128]`、`A = 255`（精确）
- **⚠️ 特别提醒**：直觉上「红色 50% 盖白底」容易写成 `0xFF7F7F7F`（灰）。**错。** 红色分量仍然被拉满到 255，只有 G/B 被压到 127。
  如果断言写成灰色，会把**正确实现判成失败**。这条是本文件最容易被写错的地方。
- **失败定位**：
  - 得到 `0xFF7F7F7F` → 混合方式传成了「叠加/多值混合」而不是 SrcOver(3)，或 alpha 被当成 255/2 直接除。
  - 得到 `0xFFFF0000` → alpha 丢了（`绘制颜色` 的第二个参数被当成了别的含义）。
  - 得到 `0x80FF7F7F` → `alphaType` 用了 `UNPREMUL(3)`，读回的是非预乘值。

### 用例 6：路径布尔运算（并集）联动

- **目的**：验证「路径运算 → 绘制」链路，且用**像素计数**做整体断言（比逐点断言更难蒙对）。
- **序列**：200×200 画布 → `清空 (0xFFFFFFFF)` → 建路径甲 `(0,0,100,100)`、路径乙 `(50,50,150,150)`（各用 `路径构建器.追加矩形` 后 `取出路径`）→ `Skia路径运算.运算 (路径甲, 路径乙, 2, 结果路径)`（运算方式 2 = 并集）→ 画笔 `置抗锯齿 (假)`/`置样式 (0)`/`置颜色 (0xFF123456)` → `绘制路径 (结果路径, 画笔)`。
- **期望（可精确计算）**：
  - 并集面积 `= 100×100 + 100×100 − 50×50 = 10000 + 10000 − 2500 = 17500` 像素
  - 非背景像素计数 **= 17500**
- **辅助逐点断言**：
  - 属于并集：`(25,25)`、`(125,125)`、`(75,75)`（交集区）→ `0xFF123456`
  - 不属于并集：`(25,125)`、`(125,25)`、`(175,175)` → `0xFFFFFFFF`
- **容差**：
  - 计数 **0 容差**（AA 关 + 整数坐标 ⇒ 边界确定）
  - 颜色 **0 容差**
- **失败定位**：
  - 计数 ≈ 20000 → 运算方式被当成「相加/异或替代」，实际画了两个矩形叠一起（重叠区被画两次，最终像素数还是 20000 − 2500 的可见区域 = 17500… **注意**：如果两矩形都画但重叠区同色，可见像素数同样是 17500。所以 **必须同时看逐点断言**：真正的区分点是 `(75,75)` 是否为目标色，以及 `(25,125)` 是否仍为背景 —— 若路径运算失效成「只画了甲」，则 `(125,125)` 会是背景色）。
  - 计数 ≈ 10000 → 只画了其中一个矩形（`运算` 返回假被忽略）。
  - 计数 ≈ 15000 → 算成了「差集」之类。
- **额外价值**：这条用例同时覆盖了 `路径构建器.追加矩形` / `取出路径`（所有权转移）/ `路径运算.运算`，是**跨类集成断言**，最接近真实使用。

## 三、容差规则总表

| 情形 | 规则 |
|---|---|
| `清空` / 纯色全画幅填充 | 精确相等，0 容差 |
| 无 AA 的几何边界（矩形/裁剪/路径） | 精确相等，0 容差 |
| 涉及 AA 或描边取整 | 每通道 ±1；像素计数给区间但必须记录精确值 |
| 半透明叠加 | 每通道 ±1，alpha 通道期望 255 时按精确 |
| 像素计数（面积类断言） | 0 容差（前提：AA 关 + 整数坐标） |

**任何时候都不允许「看起来对」「大致是红色」这种结论。**

## 四、失败时的通用定位手法

1. **先看用例 0**。用例 0 不过 → 后面的失败都是环境问题，不要报成 wsv 缺陷。
2. **打印 3×3 邻域**：第一个不符的像素 `(x,y)` 周围 9 个值一起打印。边界错 1 像素和通道错位，看邻域一眼就能分开。
3. **打印整行/整列**：描边与裁剪类问题，把 `y = 50` 整行或 `x = 50` 整列 dump 出来，覆盖区间一目了然。
4. **二分怀疑对象**：先用「纯 `清空`」验证像素通路（用例 1），再逐层加绘制。通路不对时不要去怀疑路径布尔运算。
5. **改一个参数只改一个**：`alphaType`、`colorType`、`行字节数` 三个是独立变量，一次只动一个。
6. **报缺陷时必须带**：用例号 + 实际值 + 期望值 + 该像素邻域 + 画布参数（宽/高/行字节/colorType/alphaType）。缺一项工程师就得重跑一遍。

## 七、执行结果（2026-10-30 实测，43 项断言全过）

### 执行过程中确认的三件事（都是**测试侧**问题，不是 wsv 缺陷）

1. **`取字节集数据 (…, 字节)` 会把 `0xFF` 符号扩展成 `-1`**。读通道必须 `如果 (值 < 0) { 值 = 值 + 256 }`，否则 `R=255` 会读成 `-1`，看起来像"红色通道没写进去"。
2. **`画布.裁剪矩形` 会一直生效**，必须用 `保存状态 () / 恢复状态 ()` 包住，否则会污染后续用例（我就被坑了一轮：用例5 画在裁剪切区外，读到全白，一度怀疑 `绘制颜色` 不混合）。
3. **并集行计数要选内部行**。`(0,0,100,100)` 在 `y=100` 已经不覆盖（右/下开区间），`y=100` 只有第二个矩形 → 100 px。我最初断言 150 px 是**断言写错**，实现是对的。改用 y=25 / y=60 / y=125 三行后无歧义。

### 结论

`Skia画布 + Skia画笔 + Skia路径构建器 + Skia路径运算 + Skia图像信息` 的像素级行为**全部符合预期**：通道序（B,G,R,A）、几何边界（左闭右开）、描边居中取整、裁剪语义、预乘 alpha 混合、路径布尔并集，均无障碍。
**未发现任何 wsv 像素级缺陷。**

### 用例 8（模糊）根因已定位并实测证实：`cropRect` 无法表达"不裁剪"

**三个对照的数据（11 用例 / 73 项断言）**

| 对照 | 数据 | 结论 |
|---|---|---|
| 8  `新建_模糊 (30,30,0, 空对象, 空对象)` | 采样 `(40,100)=(45,100)=(100,100)=-1`（0xFFFFFFFF）；对照（不置滤镜）`(100,100)=-16777216` 正常 | 输出被裁光 |
| **8b `新建_模糊 (30,30,0, 空对象, 矩形 (0,0,200,200))`** | `(45,100)=-6776680`、`(100,100)=-14277082`，通道 **BGRA = 38/38/38/255** | ✅ **模糊正常工作** |
| 9  颜色矩阵反色（内联 C 写 20 float） | `(100,100) = -16711681`，通道 **BGRA = 255/255/0/255**（alpha=255） | ✅ 通过 |
| 9b 按模式反色 | `-16711681` | ✅ 通过 |

**根因**（team-lead 读代码定位，我用 8b 实测证实）：
`Skia效果.wsv:915` 把 `cropRect` 声明成值类 `Skia矩形`，生成的 C 是
`sk_imagefilter_new_blur(..., (const sk_rect_t*)@<裁剪矩形>.@n<Skia矩形.数据>.GetPtr())`。
C 原型里 `cropRect` 可为 `nullptr`（= 不裁剪），但值类的 `GetPtr()` **永远非 null**，默认构造是 `{0,0,0,0}` → **0×0 裁剪区 → 输出被裁光**。
→ 只要显式给一个覆盖画布的矩形（用例 8b），模糊立即正常。
**这不是"绘制被丢弃"，也不是"全透明"，是被裁成 0×0。**

**对照 2 的答案（A 还是 B）**：用例 8 读到整像素 `-1`，而 `-1 = 0xFFFFFFFF` 的 alpha 字节就是 **255** ⇒ **alpha 没有被清零，是不符合 B（全透明）**。现象是"paint 的绘制结果被裁剪掉"，不是"画了但透明"。

**临时绕过（已实测可用）**：`新建_模糊` 的裁剪矩形传一个覆盖画布的矩形即可；不要传空对象。

### 本轮的两条重要纠错（写进文档避免后人重踩）

**纠错 A：`置字节集单精度小数` 写不进浮点数组。**
```
置字节集单精度小数 (阵据, 0, -1.0)     # 实测读回 0，等于没写
取字节集小数 (阵据, 0)                # 读回同样不可信
```
后果极隐蔽：80 字节矩阵全零 ⇒ 颜色滤镜输出 `(0,0,0,0)` 全透明 ⇒ 叠在白底上仍是白 ⇒ **看起来像"绘制被丢弃"**。
我因此误报过「颜色滤镜导致整个 draw 无效」，**该结论已撤回**。
正确做法：写/读浮点数组都用内联 C —— `@ { float* m = (float*)@<阵据>.GetPtr(); m[0] = -1.0f; ... }`。

**纠错 B：`画笔.置着色器 (空对象)` 的契约，与「共享着色器需要 `加引用`」的假设。**
- 置空对象 = **清除**（实测恢复纯画笔色），不是"无操作"。
- 同一着色器置入两个画笔**不需要手动 `加引用`**，两次都生效（`置着色器` 内部每次 set 都 ref）。**"第二个画笔会禁用着色器"的担心在本实现里不成立。**
