# Skia 图形库 · 火山视窗类库

> 把 `libSkiaSharp.dll` 的 Skia C 接口封装成火山视窗（x64）类库：**770 个原生函数 → 84 个中文类**（**8 个类库文件、11,894 行、84 个类、1,149 个方法**，映射 **770/770 全部落地**），全部 CPU 软件光栅，无 GPU 依赖，不写一行 C++ 桥接代码（纯头文件绑定）。

---

## 1. 这是什么

| 项目 | 说明 |
|---|---|
| 原生库 | `libSkiaSharp.dll`（SkiaSharp C API，Skia 主版本 **154**），单文件 **12,903,776 字节（约 12.3 MB）** |
| 渲染方式 | **CPU 软件光栅**。不包含 GPU / Ganesh / Graphite 路径 —— 这是设计选择，不是缺失（见 §5） |
| 封装规模 | **770 个 `sk_*` 函数 → 84 个火山类 / 1,149 个方法**，分布在 **8 个类库文件、共 11,894 行**（方法数 = 映射落地 770 + 便利/辅助方法 379） |
| 映射进度 | **770 / 770，全部落地**（批次1 302+2、批次2 226、批次3 137+2、批次4 101）；`gen_smoke.py` 实测计数 770 |
| 封装方式 | 直接内嵌 `@ sk_xxx(...)` 调用原生 C 函数，**没有中间转发层**；不需要 `.cpp` 编译单元 |
| 运行时依赖 | `ole32.dll` / `USER32.dll` / `FONTSUB.dll` / `KERNEL32.dll`（系统自带）。另有 `d3d12.dll`、`D3DCOMPILER_47.dll` 为**延迟加载**，只有走 GPU 路径才会触发，CPU 用法永不加载 |
| 坐标系 | 原点左上角，Y 轴向下；坐标单位像素；角度单位**度**，顺时针为正 |
| 颜色 | 一律 `0xAARRGGBB` 的 32 位整数。火山 `整数` 是有符号 32 位，高位为 1 时**显示为负数**（如 `0xFF0000FF` = `-16776961`），位模式不变 |
| 包名 | `火山.Skia` |

### 类的三种形态

| 形态 | 数量（已落地 / 全量） | 特征 | 生命周期 |
|---|---|---|---|
| **值类** | 28 | 内部是一块定长 `字节集类` 缓冲（如 `Skia矩形` 16 字节），字段读写全是单次取址，不产生缓冲复制 | 无需释放，随对象回收 |

## 2. 安装（三步）

**第 1 步 · 放置文件**

把下面这些内容放进模块目录（例如 `D:\Voldev\plugins\vprj_win\classlib\user\skia\`，或任意你喜欢的目录）：

```
skia.vgrp              ← 模块定义文件（本例放工程根目录的上一级也可）
Skia核心.wsv    15 类   ← 包属性 + 值类 + 全局/颜色/画笔/路径/画布
Skia几何.wsv    15 类   ← 圆角矩形 / 区域 / 路径族 / 派生画布
Skia图像.wsv    17 类   ← 图像 / 位图 / 像素图 / 表面 / 编解码 / 图片 / 顶点
Skia流.wsv       8 类   ← 数据 / 字符串 / 流族（含文件流/内存流/动态内存写流）
Skia颜色空间.wsv  5 类   ← 颜色空间 / 传递函数 / 色度矩阵 / 色度坐标 / ICC 配置
Skia文档.wsv     4 类   ← PDF / XPS 输出 + 文档元数据 / 文档时间 / XPS 选项
Skia效果.wsv    10 类   ← 着色器 / 四类滤镜 / 混合器 / 运行时效果 / 点3 / 效果变量
Skia文字.wsv    10 类   ← 字体 / 字形 / 文字块 / 构建器 / 字体管理 / 字体样式集 / 文字工具
deps\skia\include\c\   ← 43 个 Skia C 头文件
deps\skia\lib\x64\     ← libSkiaSharp.lib（导入库，990 个符号）
deps\skia\bin\x64\     ← libSkiaSharp.dll（运行时，12.3 MB）
native\skia_include.h  ← 伞头文件（一次性 include 全部 C 头）
```

> `deps\` 与 `native\` 的相对位置不能变 —— 包属性里的头文件搜寻目录写的是 `deps\skia`、`deps\skia\include\c`、`native`（相对路径）。若你要把模块放到别处，请把这 3 个 `@视窗.头文件搜寻目录` 与 2 个 `.x64` 库路径改成**绝对路径**。

**第 2 步 · 在工程里引用模块**

在工程的 `.vprj` 里加一条 `filter2`，指向 `skia.vgrp`。路径可以写绝对路径，也可以写相对路径（本仓库示例工程写的是 `..\..\skia.vgrp`）：

```
filter2
{
    group_file_name = "..\\..\\skia.vgrp"     // 也可写 "D:\\Voldev\\...\\skia.vgrp"
    name = Skia图形库
}
```

**第 3 步 · 确认 DLL 跟着 exe 走**

模块已在包属性里配好：

```
@视窗.附属文件 = "deps\skia\bin\x64\libSkiaSharp.dll"
```

编译时它会自动复制到 exe 同目录，**不需要手工拷贝**。发布时确认 `libSkiaSharp.dll` 与 exe 在同一目录即可。

## 3. 快速开始

以下代码与 `examples\Skia示例\src\main.wsv` 里**实测通过**的「像素自检」流程一致（该方法已验证 64×64 画布清空后 4 个采样点像素值全部正确）。

### 3.1 最小可用：画布 → 画 → 读回像素

```火山程序
变量 缓冲     <类型 = 字节集类>
变量 图像信息 <类型 = Skia图像信息>
变量 画布     <类型 = Skia画布>
变量 画笔     <类型 = Skia画笔>
变量 矩形     <类型 = Skia矩形>
变量 像素地址 <类型 = 变整数>
变量 行字节   <类型 = 整数>
变量 像素     <类型 = 整数>

Skia全局.初始化 ()                                   // 进程内调一次即可, 重复调用无副作用

缓冲 = 取空白字节集 (64 * 64 * 4)                     // 64x64, 每像素 4 字节
图像信息 = Skia图像信息.新建 (64, 64)                 // 默认 BGRA_8888(6) + 预乘(2)
行字节 = 图像信息.宽 * 4                             // 也可直接用 图像信息.行字节数(变整数)

@ @<像素地址> = (intptr_t)@<缓冲>.GetPtr();           // 把缓冲地址交给原生层

画布 = Skia画布.新建_按像素 (图像信息, 像素地址, 行字节, 0)
如果 (画布.是否有效 () == 假)
{
    返回 (假)                                        // 建画布失败
}

画布.清空 (-16776961)                                // 0xFF0000FF 不透明蓝

画笔 = Skia画笔.新建 ()
画笔.置颜色 (-256)                                  // 0xFFFFFF00 不透明黄
画笔.置抗锯齿 (真)
矩形.置边界 (8.0, 8.0, 56.0, 56.0)                   // 左/上/右/下
画布.绘制矩形 (矩形, 画笔)                            // 填充

画笔.置样式 (1)                                      // 0 填充 / 1 描边 / 2 填充并描边
画笔.置线宽 (3.0)
画布.绘制矩形 (矩形, 画笔)                            // 描边

画笔.释放 ()
画布.释放 ()                                        // ⚠ 必须先释放画布, 再读缓冲

像素 = 取字节集数据 (缓冲, (32 * 64 + 32) * 4, 整数)  // 读中心像素, 偏移 = (y*宽 + x)*4
```

要点：
- **`缓冲` 必须比 `画布` 活得久** —— `新建_按像素` 是零拷贝入口（见 §4.2），画布直接往这块内存里画。
- 画完先 `画布.释放 ()` 再读 `缓冲`，确保 Skia 内部把指令刷完。
- 读像素用 `取字节集数据 (缓冲, 偏移, 整数)`，偏移 = `(纵坐标 * 宽 + 横坐标) * 4`。

### 3.2 用路径画复杂图形

```火山程序
变量 构建器 <类型 = Skia路径构建器>
变量 路径   <类型 = Skia路径>

构建器 = Skia路径构建器.新建 ()
构建器.移动到 (0.0, 0.0)
构建器.直线到 (100.0, 50.0)
构建器.追加矩形 (矩形, 0)                             // 第二参数: 0 顺时针 / 1 逆时针
路径 = 构建器.取出路径 ()                             // 转移所有权, 构建器变空
画布.绘制路径 (路径, 画笔)
路径.释放 ()
构建器.释放 ()
```

### 3.3 画文字（字体链路：样式 → 字体管理 → 字形 → 字体 → 测量 → 绘制）

```火山程序
变量 字体样式甲 <类型 = Skia字体样式>
变量 字体管理甲 <类型 = Skia字体管理>
变量 字形甲   <类型 = Skia字形>
变量 绘制字体 <类型 = Skia字体>
变量 文字宽   <类型 = 小数>

字体管理甲 = Skia字体管理.取默认 ()                        // 静态; 系统字体管理器(内部单例)
字体样式甲 = Skia字体样式.新建 (400, 5, 0)                  // 粗细 400 常规 / 宽度等级 5 常规 / 倾斜 0 直立
字形甲 = 字体管理甲.按族名取字形 ("SimHei", 字体样式甲)      // ⚠ 样式**不能传空对象**, 传空对象实测直接崩
绘制字体 = Skia字体.新建_按字形 (字形甲, 24.0)              // 字号 24; 横向比例/倾斜有默认值

文字宽 = 绘制字体.取文字宽度 ("中")                         // 纯火山组合, 实测 = 24(字号 24)
画布.绘制简单文字 (文本到UTF8 ("中", 假), 0, 8.0, 44.0, 绘制字体.取句柄, 画笔)
//   第 1 参是**字节集类**(UTF-8 字节流), 必须 文本到UTF8 转换; 直接传文本型编不过
//   第 5 参是 变整数 句柄 → 用 绘制字体.取句柄（**属性读, 不加括号**）
//   实测: 用 -16777216 作黑色时, 非背景色像素 = 146 个

绘制字体.释放 ()
字形甲.释放 ()
字体样式甲.释放 ()
字体管理甲.释放 ()
```

> **三个必须知道的坑**
> 1. `按族名取字形` 的**样式参数不能传空对象**（空对象 ≠ 常规 400，实测直接崩），必须传 `Skia字体样式.新建 (400, 5, 0)` 的真实对象。
> 2. `绘制简单文字` 的文字参数是**字节集类**（UTF-8 字节流），要用 `文本到UTF8 (文字, 假)` 转换；直接传文本型编译不过。
> 3. `取句柄` 是**属性读**，调用**不加括号**（`绘制字体.取句柄`）；`取文字宽度` / `取字号` 是普通方法，**必须加括号**。

## 4. 八条必须读的使用约定

> 这八条都是实测踩出来的，违反其中任何一条都会出现崩溃、错误结果或"画了等于没画"。

### 4.1 句柄必须显式 `释放 ()`

**本模块的 `类_清理` 一律不做任何事。** 原因：火山的值类语义在赋值 / 传参 / 返回时按值复制，多个副本会共享同一个原生句柄；若在 `类_清理` 里自动销毁，副本逐个回收时就会重复 `delete`，实测表现为 `STATUS_HEAP_CORRUPTION (0xC0000374)` 崩溃。

规则：
- **每个 `新建` 配一个 `释放`**。`克隆` / `快照` / `取出` / `加引用` 出来的新句柄同样各自 `释放`。
- 忘记释放只会**内存泄漏，不会崩溃** —— 所以宁可少释放，也不要多释放。
- `释放` 可重复调用（内部先判 `对象指针 == 0` 直接返回）。
- 借用句柄（`是否拥有句柄 = 假`，如 `Skia表面.取画布`、`Skia画笔.取着色器`）**不要释放**，`释放` 只会清掉火山侧指针。

### 4.2 五个"零拷贝"入口有生命周期风险

| 零拷贝入口 | 替代的安全入口 |
|---|---|
| `Skia画布.新建_按像素` | 用 `Skia表面.新建_光栅` 后 `取画布` |
| `Skia图像.新建_按像素内存` | `Skia图像.新建_按像素拷贝` |
| `Skia表面.新建_光栅直通` | `Skia表面.新建_光栅` |
| `Skia位图.安装像素` | `Skia位图.尝试分配像素` |
| `Skia位图.安装像素_按像素图` | `Skia位图.尝试分配像素` + 自行拷贝 |

这五个方法**不复制像素内存**：原生 `releaseProc` 固定传 `nullptr`，含义是 **Skia 既不复制、也不释放、也不告警**。调用方必须保证那块内存在对象存活期内一直有效，提前释放会导致崩溃。**不确定生命周期时，一律改用右列的安全入口。**

### 4.3 默认像素格式：BGRA_8888(6) + 预乘(2)

`Skia图像信息.新建 (宽, 高)` 就是 `颜色类型 = 6 (BGRA_8888)` + `透明度类型 = 2 (PREMUL)`，内存字节序为 **B,G,R,A** —— 这正是 Windows DIB / `位图对象类` 能直接显示的顺序，**不需要任何转换**。

需要别的格式时用 `Skia图像信息.新建_完整 (宽, 高, 颜色类型, 透明度类型)`：`4` = RGBA_8888，`6` = BGRA_8888；透明度 `1` 不透明 / `2` 预乘 / `3` 非预乘。

如果拿到的是 RGBA 数据要转 BGRA，用 `Skia颜色.交换红蓝通道 (结果缓冲, 源缓冲, 像素数)`。

**半透明叠加的期望值算例**（写像素断言时最容易写错的地方）：50% 红叠在白底上，预乘 SrcOver 的正确结果是 **`0xFFFF7F7F`**（R=255、G=B=127），**不是**灰色 `0xFF7F7F7F`。因为红通道是 `128 + 255×127/255 = 255`（预乘后源红 = 128、目标红被 1-α 削弱到 127，相加溢出被钳到 255）。这个值已被像素级验证实测命中，写断言时请照抄。

### 4.4 `加引用` 只对 9 个类型有效，另 7 个是一次性的

| 可以 `加引用` 后复用（9 个） | 原生没有 ref，只能一次性使用（7 个） |
|---|---|
| `Skia图像`、`Skia着色器`、`Skia遮罩滤镜`、`Skia数据`、`Skia图片`、`Skia文字块`、`Skia顶点`、`Skia混合器`、`Skia颜色空间` | `Skia图像滤镜`、`Skia颜色滤镜`、`Skia运行时效果`、`Skia路径效果`、`Skia字形`、`Skia表面`、`Skia字体样式集` |

- 右列 7 个：**置入画笔/字体后不要再释放，也不要交给第二个使用者**，需要第二份就重新 `新建`。
- 左列 9 个：`加引用 ()` 之后可以安全地交给多个画笔 / 缓存；`释放` 与 `加引用` 一一配对。
- 特别注意 `Skia字形`：一个字形只能置入一个 `Skia字体`，两个字体要用同一字体面就各取一次。

### 4.5 裁剪枚举：`0` 是"挖去"，`1` 才是"取交"

`裁剪矩形 (矩形, 裁剪方式, 抗锯齿)` 的第二个参数是 `sk_clipop_t`：

| 值 | 含义 |
|---|---|
| `0` | `DIFFERENCE` —— **挖去**该矩形（裁剪区变小，像打了个洞） |
| `1` | `INTERSECT` —— **取交**，常规裁剪必须传这个 |

正确写法：`画布.裁剪矩形 (矩形, 1, 真)`。传 0 会让后续绘制"消失"，这是最容易被误判成"画不出来"的坑。同样适用于 `裁剪路径` / `裁剪圆角矩形` / `裁剪区域`。

### 4.6 裁剪会一直生效，直到 `恢复状态`

**`裁剪矩形` / `裁剪路径` / `裁剪区域` 不是"只影响下一次绘制"，而是持续影响后续所有绘制**，作用范围一直延续到对应的 `恢复状态`。而且**忘了恢复也不会有任何报错** —— 表现就是"后面全画不出来"。

只想局部裁剪，必须这样配对：

```火山程序
画布.保存状态 ()
画布.裁剪矩形 (区域, 1, 真)          // 第 2 参数 1 才是"取交", 0 是"挖去"
画布.绘制路径 (路径, 画笔)
画布.恢复状态 ()                     // ← 少了这一行, 之后的绘制全部被裁掉, 且无任何报错
```

同理，**`保存图层 (边界, 画笔)` 必须与 `恢复状态` 严格配对**（每次 `保存图层` 恰好一次 `恢复状态`）。少恢复会让图层栈泄漏、后续绘制偏移或整片丢失；多恢复则会把外层的状态（矩阵/裁剪）提前弹掉。

> 排查口诀：**"画不出来"先查裁剪（是否忘了 `恢复状态`、`裁剪方式` 是否传了 0），再查画笔样式（描边 + 线宽 0 = 看不见）。**

### 4.7 颜色必须按 `0xAARRGGBB` 装进**有符号 32 位**：不透明黑是 `-16777216`，不是 `0`

火山 `整数` 是有符号 32 位，`0xFF000000`（不透明黑）必须写成 **`-16777216`**。**写 `0` 得到的是"全透明黑"** —— `0x00000000` 的 alpha = 0，等于**什么都没画**，而且不会报任何错。

| 想要的颜色 | 正确写法 | 常见错误写法 |
|---|---|---|
| 不透明黑 | `-16777216`（`0xFF000000`） | ❌ `0` → 全透明黑，画了等于没画 |
| 不透明白 | `-1`（`0xFFFFFFFF`） | — |
| 不透明红 | `-65536`（`0xFFFF0000`） | — |
| 不透明蓝 | `-16776961`（`0xFF0000FF`） | — |
| 50% 透明黑（`0x80000000`） | `-2147483648` | — |
| 50% 灰（`0x80808080`） | `-2139062144` | — |

> 实测教训：工程师画文字时用 `0` 当黑色，结果**非背景像素数 = 0**（以为文字没画上）；改成 `-16777216` 后非背景像素 = **146**，一切正常。
> 换算方法：把 `0xAARRGGBB` 当无符号 32 位读，再减去 `2^32`。建议在代码里定义常量而不是硬编码字面量。

### 4.8 float 数组必须用**内联 C 逐元素写**，`置字节集单精度小数` 写不进去

需要给原生层传 `float[]` 时（颜色矩阵 20 个、虚线间隔、多边形点、卷积核等），**不能用 `置字节集单精度小数` —— 实测写不进去，读回恒为 0**。必须逐元素写：

```火山程序
@ ((float*)@<数据>.GetPtr())[@<序号>] = (float)@<值>;
```

涉及的方法（**全部要求这样写**）：

| 方法 | float 个数 | 说明 |
|---|---|---|
| `Skia颜色滤镜.新建_颜色矩阵` | 20 | 4×5 行优先 |
| `Skia颜色滤镜.新建_HSLA矩阵` | 20 | 同上 |
| `Skia路径效果.新建_虚线` | 间隔个数 | 实/虚交替 |
| `Skia路径构建器.追加多边形` | 点数 × 2 | 每点 x,y |
| `Skia画布.绘制多点` | 点数 × 2 | 每点 x,y |
| `Skia矩阵.映射多点` | 点数 × 2 | 每点 x,y |
| `Skia图像滤镜.新建_矩阵卷积` | 核宽 × 核高 | 如 3×3 = 9 个 |

> 这条与 §4.7 是同一类坑：**火山的"便捷写入"在二进制缓冲上不可靠，凡是原生要 float 数组，就用内联 C + 强转逐元素写**，写完最好读回一个元素自检。

## 5. 已知缺口（如实列出）

> ✅ **文字已可用**（批次4 已落地）：`Skia字体管理` 枚举/匹配字体 → `Skia字体.置字形与字号` → `Skia画布.绘制简单文字` 或 `Skia字体.取文字宽度`。
> 实测基线：`取文字宽度 ("中") = 24`（字号 24）；绘制后非背景像素 = **146**（用 `-16777216` 当黑色时，见 §4.7）。

| 缺口 | 影响 | 现状与替代 |
|---|---|---|
| **文字对齐（居中/右对齐）、LCD 子像素渲染** | 无法直接做居中/右对齐文字，也无法控制 LCD 清晰度 | Skia v4 把 `SkPaint` 的字体属性全部移出 `sk_paint.h`，只存在于 `sk_compatpaint_*` 层，而上游没有 `sk_compatpaint.h` 头文件（只有 15 个裸导出符号），手写原型风险高于收益。**替代：用 `Skia字体.取文字宽度` 量出宽度自己算偏移**（已实测 `取文字宽度 ("中") = 24`） |
| **文字对齐（居中/右对齐）、文字编码控制、LCD 子像素渲染** | 无法直接做居中/右对齐文字，也无法控制 LCD 清晰度 | Skia v4 把 `SkPaint` 的字体相关属性全部移出了 `sk_paint.h`（该头文件在 v4 里**没有任何 text/font 符号**），只存在于 `sk_compatpaint_*` 层；而上游**没有提供 `sk_compatpaint.h` 头文件**，只有 15 个裸导出符号。手写 `extern "C"` 原型等于靠推断签名，一个参数类型错就是运行时崩溃，因此本轮不封装。**替代：用 `Skia字体.取文字宽度` 量出宽度自己算偏移（需批次4 落地）** |
| **GPU 渲染**（Ganesh `gr_*` 68 条 + Graphite 47 条） | 没有 GPU 加速、没有纹理/后缓冲区互操作 | 按模块定位（CPU 软件光栅）不封装。火山视窗侧可用 D2D/GDI 承担 GPU 加速场景 |
| **Lottie 动画**（`skottie_*` 27 + `skresources_*` 10 + `sksg_*` 7 = 44 条） | 不能播 Lottie JSON 动画 | 本轮未纳入，可作后续扩展（头文件已在 `deps` 内，技术上可做） |
| `Skia字体.绑定到画笔` | 该便利方法不存在 | v4 的 `SkPaint` 已不含字体，字体是 `绘制简单文字` 的独立参数，**无法实现**；用 `Skia字体.取文字宽度` + 显式传字体给绘制函数代替 |

> 另：`sk_managed*` 12 条（managed drawable / stream / wstream / tracememorydump）需要 C 回调桥，火山侧无法安全表达，按设计不封装。

## 7. 常见编译问题（实测）

| 现象 | 原因与处理 |
|---|---|
| `C3861: "min"/"max" 未定义` 出现在 MFC 的 `GdiplusTypes.h` | 本模块**故意不定义 `NOMINMAX`**（`@视窗.预定义宏` 是工程级，定义了会打断 MFC 头文件）。若你自己的工程需要 `NOMINMAX`，在你自己的工程级设置里定义，不要改模块 |
| `LNK1181: 无法打开 libSkiaSharprelease.lib` | 外部库名写死为 `libSkiaSharp.lib`，**不带 `$(d)` 后缀**（SkiaSharp 的导入库没有 debug/release 之分） |
| 编译通过但运行报 `0xC0000374` 堆损坏 | 有句柄被重复释放 —— 检查是否对借用对象（`是否拥有句柄 = 假`）调了 `释放`，或同一句柄被复制给两个变量后又各释放一次 |
| 画不出东西，但每一步的返回值都正常 | 九成是 §4.5 的裁剪枚举传了 `0`（挖去），或者画笔样式是描边（`1`）却把线宽设成 `0` |
| `发现了重复的名称`，指向一个局部变量 | **`字体` 是窗口基类的保留成员名**，局部变量不能叫 `字体`（也不能叫 `标题`/`宽度`/`高度` 等）。改叫 `字形对象` / `字体对象` 即可 |
| `属性读` 与普通方法调用形式不一致导致编译错 | **属性读不加括号、普通方法必须加括号**。属性读（**不加括号**）：`取句柄`、`宽`、`高`、`对象指针`、`行字节数`、`取当前偏移`；普通方法（**必须加括号**）：`取文字宽度`、`取字号`、`取线宽`、`新建`、`释放`。例：`绘制字体.取句柄` ✅ / `绘制字体.取句柄 ()` ❌；`绘制字体.取字号 ()` ✅ / `绘制字体.取字号` ❌ |
| `按族名取字形` 一调用就崩 | 样式参数**不能传"空样式对象"**（空对象 ≠ 常规 400）。必须显式建：`Skia字体样式.新建 (400, 5, 0)`（400 常规 / 5 常规宽度 / 0 直立），再传给 `按族名取字形` |

### 维护者须知（改这个模块前必读）

这两条是我们踩过并付了返工代价的**系统性错误**，加新批次前先过一遍：

> - **可空指针参数不能封装成值类。** 值类的缓冲永远非 null（默认全 0），把"可空"参数写成值类会丢掉 null 语义 —— 典型后果：`cropRect` 变成 0×0 矩形 → 裁剪把输出全裁光 → **表现为"什么都画不上"且无报错**。要么拆 `_按裁剪` / `_不裁剪` 两个变体，要么该参数用 `变整数` 地址（`0` = `nullptr`）。
> - **输出参数不能加 `const`**，即使同一结构体作为输入时是 `const`。判据：**返回 `void` 的接口、或"返回一个标量结果又额外带指针参数"的接口，那些指针多半是输出**。已知 4 例：`sk_rrect_get_rect` 第 2 参、`sk_matrix_map_rect` 第 2 参、`sk_codec_get_info` 第 2 参、`sk_bitmap/pixmap_get_info` 第 2 参。
